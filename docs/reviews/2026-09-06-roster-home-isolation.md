# Home-bound roster persistence

Date: 2026-09-06. Follow-up to the [executed upstream/current ownership audit](2026-09-06-roster-ownership-audit.md).

## Implemented

Adapted Munder's home-ownership principle without its shared mutable ownership stamp. Main now captures the configured home and projected roster together in `roster:bootSync`. Renderer snapshots use one versioned envelope containing the home and all roster slices, under `operatus.roster.v1:<encoded-home>`. A valid file, including an intentionally empty file, takes precedence over cached data. Missing/unreadable files may fall back only to their own validated cache.

Mirror writes echo the boot home. Main rejects mismatched or absent home identities before touching disk; first-write protection is tracked per home. Agents, archives, restorable entries, notes, selection and parked queues are scoped together. Existing Gauntlet restoration exclusion remains intact.

Legacy shared keys are preserved, never reassigned automatically. Invalid owned caches are also preserved instead of overwritten. A boot-time status notice identifies unavailable, invalid or unassigned data; an empty-home restart does not hide the legacy notice. Storage access/quota failures are caught, and file mirroring can still proceed. Settings no longer clears caches before requesting a fresh/moved home. Onboarding now reloads the renderer after establishing its home so the module-level store captures the new identity.

The React review informed a versioned, minimized atomic cache and accessible status notice without adding a subscription or effect. Full-story verification traced the native preload/main boundary rather than substituting a browser-only mock.
