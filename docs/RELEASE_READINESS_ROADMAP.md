# Operatus fix and release-readiness roadmap

Updated 2026-09-06. Agreed direction; work below is planned unless marked otherwise.

## Product objective

**Non-negotiable billing rule:** subscriptions only, with no API-backed feature,
fallback, paid usage-credit path or override. See the
[subscription-only ADR](architecture/adr-subscription-only.md). The first safety
interlock is implemented: this build holds all agent startup until enforceable
subscription/no-overage admission is ready. R1 cannot complete while that hold is
needed. No live inference smoke should bypass it.

Coordinate subscription-backed Claude and Codex sessions into substantial, verifiable project work while protecting the operator's attention. The distinguishing combination is conducted delegation, exact-artifact Gauntlet verification, and a legible visual office. Neither more simultaneous agents nor more animation is a success measure by itself.

The [local Mac review](reviews/2026-09-05-local-mac-readiness.md) is the current readiness baseline. The application compiles and renders, but its live autonomous loop is **not accepted for unattended important work**. This roadmap takes precedence over historical milestone acceptance language for present release readiness.

## Delivery gates

The active evaluation goal also requires an owner-operator acceptance exercise:
supervise several related and unrelated projects with concurrent Gauntlets, find
the highest-priority decision without opening every terminal, identify each
objective/owner/artifact/blocker, and distinguish capacity limits from failures.
Use task-based evidence at expanded Mac and 1920x1080 viewports. Record misses
and remediation, not a confirmation-only review. A green unit suite or attractive
idle floor cannot satisfy this exercise.

- [x] Verify Fable 5.1's documented model ID and CLI minimum; add it to the picker
  without migrating existing model choices. Offline probes confirm native Claude
  2.1.263 meets the 2.1.255 minimum; Homebrew 2.1.86 does not.
- [ ] Pin the admitted executable and check model/version/plan eligibility before
  launch. The operator uses Claude Max with paid extras/top-ups disabled. Recheck
  stale model catalogs and duplicate installation selection as part of preflight.

| Gate | Outcome | Exit evidence |
| --- | --- | --- |
| R0: preserve the failures | Reproducible startup, isolation, and restore cases | Automated regressions derived from the two recorded live smoke runs |
| R1: trustworthy local execution | One Mac can complete a genuinely conducted loop | Real-provider pass and repair/re-critique runs, intact shared checkout, correct failure and recovery behavior |
| R2: flow-preserving daily use | The operator can supervise meaningful work without terminal babysitting | Task-based viewport audit and bounded real-project dogfood |
| R3: project-scale coordination | Several work orders converge on an independently verified integrated candidate | Ownership/dependency receipts, bounded scheduling, integration Gauntlet |
| R4: multi-machine reliability | A Mac and Windows Branch can be managed without confusing authority or identity | Actual hardware enrollment, lifecycle, disconnect/reconnect and command tests |
| R5: distributable release | A reproducible, recoverable installation with honest security warnings | Platform-specific build/install/update/rollback evidence; signing where available |

Visual research and upstream comparison can proceed alongside R0/R1. Neither can substitute for their acceptance evidence. Do not bundle every long-term Firm feature into the first useful Mac release.

### Real-provider acceptance matrix

The deterministic suite is necessary but not sufficient. Add an opt-in live-provider suite using disposable repositories, explicit budgets, and installed/authenticated subscriptions. Routine CI must not silently spend subscription capacity or require private credentials.
